# Migrate the single-source model without changing content identity

The multi-source migration creates one runtime Local or SMB Corpus Source from the existing deployment configuration, assigns the continuous all-collections policy, and maps existing source-backed Projects to enabled Source Collections. It preserves those Project IDs, document IDs, indexes, conversation references, and job history while backfilling source, collection, and Source Item identity. Demo-only manually uploaded content is explicitly excluded under its removal decision. Environment values are read only to perform the idempotent first migration; afterward SQLite is authoritative and legacy values produce a one-release deprecation warning without overriding runtime configuration. Ambiguous source-backed records halt migration for administrator resolution, and the new scheduler does not start alongside the legacy watcher.
