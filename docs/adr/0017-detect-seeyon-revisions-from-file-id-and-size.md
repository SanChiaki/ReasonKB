# Detect Seeyon revisions from file ID and size

For Seeyon V8.1SP2, ReasonKB uses `fr_id` as the stable Source Item ID and the pair `file_id + fr_size` as the Source Revision. This contract is based on an observed replacement upload where `fr_id`, `fr_create_time`, and `file_name` remained unchanged while `file_id` and `fr_size` changed. A change to either revision field queues a download from the current `file_id` and re-indexes the existing ReasonKB document. `fr_create_time` is not a modification signal, and regular Seeyon scans do not download unchanged files merely to compute content hashes. The connector normalizes Seeyon IDs to opaque strings at its boundary because their signed 64-bit values exceed JavaScript's safe integer range; SQLite and application APIs must not represent them as JSON numbers.
