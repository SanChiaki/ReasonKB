# Distinguish access revocation from missing content

After Seeyon authentication succeeds, an explicit authorization denial for a registered library marks its Project as access revoked: synchronization and retrieval stop immediately, while the Project, documents, and indexes are retained for recovery. An initial HTTP 401 first triggers token renewal and one request retry; repeated 401 responses, token acquisition failures, timeouts, ambiguous errors, and server failures instead degrade the Corpus Source without changing known content. Access Revoked requires an explicit authorization denial after valid authentication, such as HTTP 403. Missing status is reserved for items absent from a complete successful listing that the current Source Principal was authorized to read. This prevents permission changes, source deletion, and transient faults from collapsing into the same lifecycle event.
